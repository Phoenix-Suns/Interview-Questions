# CHỦ ĐỀ 1: SWIFT LANGUAGE — CORE (50 CÂU)

## CẤP ĐỘ 1: JUNIOR (CƠ BẢN) - 15 Câu

### 1. Sự khác biệt cơ bản về quản lý vùng nhớ và cách truyền dữ liệu giữa hai cấu trúc dữ liệu nền tảng nhất là gì?

**Ý chính:** Value Type (`struct`) lưu trên Stack và copy khi truyền đi; Reference Type (`class`) lưu trên Heap và chia sẻ tham chiếu.
**Diễn giải:** Khi gán một cấu trúc giá trị cho biến mới, hệ thống tạo bản sao độc lập. Ngược lại, cấu trúc tham chiếu chỉ truyền địa chỉ ô nhớ, thay đổi ở một nơi sẽ làm thay đổi toàn cục đối tượng đó.
**Ví dụ:**

```swift
struct Point { var x: Int }
var p1 = Point(x: 0)
var p2 = p1
p2.x = 10 // p1.x vẫn là 0

class User { var age: Int = 0 }
let u1 = User()
let u2 = u1
u2.age = 20 // u1.age cũng thành 20

```

### 2. Hai từ khóa cốt lõi dùng để khai báo định danh khác biệt nhau như thế nào trong quá trình biên dịch?

**Ý chính:** `let` định nghĩa hằng số (Immutable), `var` định nghĩa biến (Mutable).
**Diễn giải:** Sử dụng hằng số giúp mã nguồn an toàn hơn, ngăn chặn sự thay đổi vô tình và cho phép trình biên dịch tối ưu hóa bộ nhớ tốt hơn.
**Ví dụ:**

```swift
let name = "Swift"
// name = "iOS" // Lỗi compile

var version = 5.0
version = 6.0 // Hợp lệ

```

### 3. Cấu trúc nào tốt nhất để gom nhóm một danh sách giới hạn các trường hợp có thể xảy ra trong hệ thống?

**Ý chính:** `enum` (Enumeration).
**Diễn giải:** Giúp định nghĩa một kiểu dữ liệu an toàn (type-safe) có giới hạn cố định. Trình biên dịch bắt buộc phải xử lý tất cả các trường hợp khi sử dụng vòng lặp kiểm tra.
**Ví dụ:**

```swift
enum ResultState {
    case success, failure, loading
}
let currentState = ResultState.loading

```

### 4. Kiểu dữ liệu nào đại diện cho việc một biến có thể chứa giá trị thực tế hoặc không chứa gì cả?

**Ý chính:** `Optional` (`?`).
**Diễn giải:** Giải quyết vấn đề null pointer exception. Nó thực chất là một enum với hai case: `.some(Wrapped)` và `.none`.
**Ví dụ:**

```swift
var age: Int? = 25
age = nil // Hợp lệ

```

### 5. Cú pháp nào giúp mở gói an toàn một biến có thể rỗng và thoát khỏi hàm ngay lập tức nếu biến đó không có giá trị?

**Ý chính:** `guard let`.
**Diễn giải:** Giúp kiểm tra giá trị tồn tại mà không tạo ra các khối lệnh lồng nhau (pyramid of doom). Nếu điều kiện sai, buộc phải gọi lệnh thoát sớm (`return`, `break`, `throw`).
**Ví dụ:**

```swift
func process(name: String?) {
    guard let validName = name else { return }
    print("Xử lý: \(validName)")
}

```

### 6. Cú pháp nào giúp mở gói an toàn một biến rỗng nhưng chỉ để sử dụng trong một phạm vi hẹp nội bộ?

**Ý chính:** `if let`.
**Diễn giải:** Dùng khi bạn chỉ muốn chạy một đoạn mã khi biến có giá trị, và biến mở gói chỉ tồn tại bên trong khối lệnh đó.
**Ví dụ:**

```swift
var code: Int? = 200
if let validCode = code {
    print("Mã là \(validCode)")
}

```

### 7. Thuộc tính nào không lưu trực tiếp giá trị vào bộ nhớ mà sẽ tính toán lại mỗi khi được gọi đến?

**Ý chính:** Computed Property (Thuộc tính tính toán).
**Diễn giải:** Không chiếm thêm bộ nhớ tĩnh. Nó cung cấp các khối `get` (và tùy chọn `set`) để truy xuất hoặc thay đổi dữ liệu từ các nguồn khác.
**Ví dụ:**

```swift
struct Rect {
    var width: Double
    var height: Double
    var area: Double { return width * height }
}

```

### 8. Cơ chế nào giúp kích hoạt một đoạn mã tự động ngay trước và sau khi một biến lưu trữ thay đổi giá trị?

**Ý chính:** Property Observers (`willSet` và `didSet`).
**Diễn giải:** Cho phép theo dõi sự thay đổi của thuộc tính lưu trữ. Rất hữu ích để cập nhật giao diện (UI) ngay khi dữ liệu thay đổi.
**Ví dụ:**

```swift
var score: Int = 0 {
    didSet { print("Điểm mới: \(score), cũ: \(oldValue)") }
}

```

### 9. Khái niệm nào dùng để tạo ra một bản thiết kế (blueprint) chứa các phương thức và thuộc tính mà không có thân hàm cụ thể?

**Ý chính:** `Protocol` (Giao thức).
**Diễn giải:** Định nghĩa khuôn mẫu hành vi. Bất kỳ cấu trúc dữ liệu nào tuân thủ nó đều phải tự viết logic chi tiết cho các yêu cầu đó.
**Ví dụ:**

```swift
protocol Vehicle {
    func startEngine()
}

```

### 10. Cách nào để thêm trực tiếp một chức năng mới vào kiểu dữ liệu Int hoặc String của hệ thống mà không cần kế thừa?

**Ý chính:** `Extension` (Tiện ích mở rộng).
**Diễn giải:** Có thể mở rộng chức năng (thêm hàm, thuộc tính tính toán) cho bất kỳ struct, class, enum hay protocol nào mà không làm ảnh hưởng đến mã nguồn gốc.
**Ví dụ:**

```swift
extension Int {
    var isEven: Bool { self % 2 == 0 }
}

```

### 11. Cơ chế đóng gói một đoạn mã thành một biến để truyền đi khắp nơi và thực thi sau này được gọi là gì?

**Ý chính:** `Closure`.
**Diễn giải:** Khối lệnh tự chứa (anonymous function). Có thể lưu tham chiếu và bắt (capture) các giá trị của môi trường xung quanh nó.
**Ví dụ:**

```swift
let sayHello = { (name: String) in
    print("Hello \(name)")
}
sayHello("Swift")

```

### 12. Từ khóa nào xác định một hàm có khả năng phát sinh ra sự cố trong quá trình chạy?

**Ý chính:** `throws`.
**Diễn giải:** Dùng trong Error Handling. Nó thông báo cho người gọi hàm phải chuẩn bị sẵn khối lệnh xử lý sự cố (bằng `try` và `do-catch`).
**Ví dụ:**

```swift
func readFile() throws -> String { return "Data" }

```

### 13. Phân quyền nào ngăn chặn tuyệt đối việc truy cập một biến từ bất kỳ file nào khác ngoại trừ file đang chứa nó?

**Ý chính:** `fileprivate`.
**Diễn giải:** Cho phép các kiểu dữ liệu khác nhau nhưng nằm cùng chung một file vật lý (tệp `.swift`) có thể truy cập lẫn nhau.
**Ví dụ:**

```swift
fileprivate var secretToken = "ABC"

```

### 14. Kiểu dữ liệu linh hoạt dùng để gom nhóm nhiều giá trị khác kiểu thành một khối tạm thời mà không cần định nghĩa cấu trúc mới là gì?

**Ý chính:** `Tuple`.
**Diễn giải:** Hữu ích khi muốn trả về nhiều giá trị từ một hàm mà không cần tạo hẳn một `struct` hay `class`.
**Ví dụ:**

```swift
func getStatus() -> (code: Int, message: String) {
    return (200, "OK")
}

```

### 15. Kỹ thuật ép kiểu ở thời điểm chạy, trả về nil nếu đối tượng không thuộc kiểu mong muốn là gì?

**Ý chính:** Conditional Type Casting (`as?`).
**Diễn giải:** Cố gắng chuyển đổi kiểu dữ liệu (thường là từ kiểu cha xuống kiểu con). Nếu thất bại sẽ trả về `nil` thay vì crash app.
**Ví dụ:**

```swift
let animal: Any = "Dog"
let dogString = animal as? String

```

## CẤP ĐỘ 2: MIDDLE (TRUNG CẤP) - 15 Câu

### 16. Yêu cầu bắt buộc khi một khối lệnh được truyền vào hàm nhưng lại chỉ được gọi thực thi sau khi hàm đó đã kết thúc là gì?

**Ý chính:** Đánh dấu bằng `@escaping`.
**Diễn giải:** Trình biên dịch cần biết khối lệnh sẽ "thoát" khỏi vòng đời của hàm để nó giữ lại khối lệnh và các vùng nhớ liên quan trên Heap thay vì giải phóng ngay.
**Ví dụ:**

```swift
var handlers: [() -> Void] = []
func saveHandler(_ block: @escaping () -> Void) {
    handlers.append(block) // Thoát khỏi hàm
}

```

### 17. Cú pháp nào dùng trong thân khối lệnh để ngăn chặn tình trạng hai đối tượng giam giữ bộ nhớ của nhau vĩnh viễn?

**Ý chính:** Capture List (`[weak self]`).
**Diễn giải:** Bẻ gãy Retain Cycle bằng cách khai báo biến bị bắt bên trong closure dưới dạng tham chiếu yếu (không tăng Reference Count).
**Ví dụ:**

```swift
func load() {
    service.fetch { [weak self] data in
        self?.updateUI(data)
    }
}

```

### 18. Giải pháp nào giúp trì hoãn việc cấp phát bộ nhớ cho một thuộc tính nặng nề cho đến khi người dùng gọi nó lần đầu tiên?

**Ý chính:** Khai báo bằng từ khóa `lazy`.
**Diễn giải:** Khởi tạo thuộc tính được dời lại đến thời điểm truy cập đầu tiên. Thường dùng cho các object mất nhiều thời gian khởi tạo hoặc phụ thuộc vào thông tin khác.
**Ví dụ:**

```swift
class ViewManager {
    lazy var heavyView: UIView = UIView()
}

```

### 19. Cơ chế tự động gói gọn một biểu thức thông thường thành một khối lệnh không tham số để trì hoãn việc tính toán là gì?

**Ý chính:** `@autoclosure`.
**Diễn giải:** Giúp mã nguồn gọi hàm trông sạch sẽ hơn (không cần cặp ngoặc nhọn `{}`) trong khi vẫn tận dụng được tính năng lazy evaluation của closure.
**Ví dụ:**

```swift
func assertCheck(_ condition: @autoclosure () -> Bool) {
    if !condition() { print("Lỗi") }
}
assertCheck(1 > 2) // Gọi như biểu thức bình thường

```

### 20. Từ khóa nào cho phép một phương thức thuộc cấu trúc giá trị có quyền thay đổi các thuộc tính nội tại của nó?

**Ý chính:** `mutating`.
**Diễn giải:** `struct` là Value Type nên mặc định các hàm bên trong không được đổi trạng thái. Khi thêm `mutating`, hàm thực chất sẽ tạo ra một bản sao mới và ghi đè lên đối tượng cũ.
**Ví dụ:**

```swift
struct Counter {
    var count = 0
    mutating func increase() { count += 1 }
}

```

### 21. Cấu trúc nào cho phép viết một hàm xử lý linh hoạt cho mọi loại dữ liệu miễn là chúng tuân thủ một bộ quy tắc nhất định?

**Ý chính:** Generics (`<T>`).
**Diễn giải:** Giúp tái sử dụng mã nguồn, đảm bảo Type-Safety ở compile-time. Trình biên dịch sẽ kiểm tra kiểu truyền vào mà không phải ép kiểu ở runtime.
**Ví dụ:**

```swift
func swap<T>(_ a: inout T, _ b: inout T) {
    let temp = a; a = b; b = temp
}

```

### 22. Cách thiết lập một kiểu dữ liệu ẩn danh đại diện bên trong định nghĩa của một bản thiết kế hành vi (giao thức) là gì?

**Ý chính:** `associatedtype`.
**Diễn giải:** Nó giống như Generics nhưng dành cho Protocol. Kiểu thực sự sẽ do `struct/class` quyết định khi chúng tuân thủ protocol đó thông qua `typealias`.
**Ví dụ:**

```swift
protocol Container {
    associatedtype Item
    mutating func add(_ item: Item)
}

```

### 23. Kỹ thuật tái sử dụng mã bằng cách cung cấp sẵn logic mặc định cho các yêu cầu của một bản thiết kế hành vi là gì?

**Ý chính:** Protocol Extension.
**Diễn giải:** Giúp loại bỏ việc phải viết lại cùng một đoạn mã cho mọi object tuân thủ Protocol. Nền tảng của Protocol-Oriented Programming.
**Ví dụ:**

```swift
protocol Describable { }
extension Describable {
    func describe() { print("Đây là object") }
}

```

### 24. Cú pháp nào để gói gọn logic xử lý chung (ví dụ lưu trữ, giới hạn độ lớn) cho nhiều thuộc tính khác nhau một cách tái sử dụng?

**Ý chính:** Property Wrapper (`@propertyWrapper`).
**Diễn giải:** Tách biệt logic quản lý dữ liệu khỏi logic business. Sử dụng phổ biến trong SwiftUI (`@State`, `@Binding`) và quản lý cache.
**Ví dụ:**

```swift
@propertyWrapper
struct Clamp {
    var wrappedValue: Int { didSet { wrappedValue = max(0, wrappedValue) } }
    init(wrappedValue: Int) { self.wrappedValue = max(0, wrappedValue) }
}

```

### 25. Hàm bậc cao nào dùng để chuyển đổi từng phần tử trong một danh sách thành danh sách mới với kiểu dữ liệu khác?

**Ý chính:** `map`.
**Diễn giải:** Tránh dùng vòng lặp `for` thủ công, tạo mã ngắn gọn, declarative.
**Ví dụ:**

```swift
let numbers = [1, 2, 3]
let strings = numbers.map { String($0) }

```

### 26. Từ khóa nào được dùng để truyền một biến vào hàm, thay đổi giá trị của nó, và giữ lại giá trị mới đó sau khi thoát hàm?

**Ý chính:** `inout`.
**Diễn giải:** Về bản chất, nó copy giá trị vào hàm, và copy ngược kết quả ghi đè ra biến ngoài khi hàm kết thúc (Copy-in copy-out).
**Ví dụ:**

```swift
func double(_ value: inout Int) { value *= 2 }
var x = 5
double(&x) // x = 10

```

### 27. Cách nhóm các cấu trúc dữ liệu nhỏ nằm gọn bên trong định nghĩa của một cấu trúc dữ liệu lớn hơn để tránh xung đột tên gọi là gì?

**Ý chính:** Nested Types.
**Diễn giải:** Tạo ra cấu trúc phân cấp (namespace), giúp thể hiện rõ ràng rằng kiểu dữ liệu này chỉ phục vụ riêng cho kiểu dữ liệu bao bọc nó.
**Ví dụ:**

```swift
struct Message {
    enum Status { case sent, read }
    var status: Status
}

```

### 28. Cấu trúc chuẩn nào của hệ thống chuyên dùng để gói gọn cả hai trường hợp: xử lý thành công trả về dữ liệu và xử lý thất bại trả về lỗi?

**Ý chính:** `Result<Success, Failure>`.
**Diễn giải:** Biến đổi Error Handling truyền thống sang hướng functional. Giảm rủi ro quên xử lý lỗi trong các callback bất đồng bộ.
**Ví dụ:**

```swift
func fetch() -> Result<String, Error> {
    return .success("Data")
}

```

### 29. Cấu trúc enum hỗ trợ việc lưu trữ các dữ liệu phụ kèm theo từng trường hợp cụ thể được gọi là gì?

**Ý chính:** Enum Associated Values.
**Diễn giải:** Khác với Raw Value (cố định), Associated Value biến enum thành các container linh hoạt có thể mang theo tham số động cho mỗi case.
**Ví dụ:**

```swift
enum Barcode {
    case qrCode(String)
    case upc(Int, Int, Int)
}

```

### 30. Loại khối lệnh bắt buộc phải cung cấp đủ tất cả giá trị tham số khi khởi tạo đối tượng gọi là gì?

**Ý chính:** Designated Initializer (Hàm khởi tạo chỉ định).
**Diễn giải:** Trách nhiệm của nó là đảm bảo mọi thuộc tính (không optional) của class đều được cấp phát vùng nhớ hợp lệ trước khi object sẵn sàng sử dụng.
**Ví dụ:**

```swift
class Person {
    var name: String
    init(name: String) { self.name = name }
}

```

## CẤP ĐỘ 3: SENIOR (NÂNG CAO) - 20 Câu (Chuyên sâu Protocol, Generics & Memory)

### 31. Sự khác biệt ở cấp độ biên dịch và quản lý bộ nhớ giữa hai hình thức khai báo trừu tượng `some` và `any` trong Swift 5.7+ là gì?

**Ý chính:** `some` (Opaque Type) bảo tồn kiểu tĩnh (Static Dispatch); `any` (Existential Type) đóng gói ở runtime (Dynamic Dispatch qua Existential Container).
**Diễn giải:** `some` bắt buộc compiler xác định duy nhất 1 kiểu ngầm định, giúp giữ lại Type Identity, tối ưu hóa bộ nhớ và hiệu năng. `any` cho phép lưu các kiểu heterogeneous, nhưng tốn chi phí boxing (3-word buffer) và vtable lookup.
**Ví dụ:**

```swift
protocol Shape {}
struct Circle: Shape {}
// Tối ưu compile-time (biết chính xác trả về Circle)
func getShape() -> some Shape { Circle() } 
// Đóng gói runtime (chứa box)
func getAnyShape() -> any Shape { Circle() } 

```

### 32. Kỹ thuật nào giúp vượt qua rào cản không thể lưu trữ các cấu trúc giao thức có chứa kiểu ẩn danh vào một danh sách?

**Ý chính:** Type Erasure (Xóa kiểu).
**Diễn giải:** Khi Protocol có `associatedtype`, nó không thể đứng độc lập như một Type thông thường. Ta phải tạo một struct Generic (như `AnyPublisher`, `AnySequence`) đóng gói protocol đó lại, đẩy việc xác định kiểu lên cấp Generic Wrapper.
**Ví dụ:**

```swift
struct AnyStorage<T> {
    private let _get: () -> T
    init<S: Storage>(_ storage: S) where S.Item == T {
        _get = storage.get
    }
}

```

### 33. Khi một cấu trúc giá trị (Value Type) chứa bên trong nó một thuộc tính tham chiếu (Reference Type), điều gì xảy ra với bộ nhớ khi ta sao chép cấu trúc đó?

**Ý chính:** Struct được sao chép (Stack), nhưng con trỏ bên trong vẫn trỏ cùng tới một đối tượng (Heap). (Shallow Copy).
**Diễn giải:** Điều này phá vỡ tính "độc lập trạng thái" của Value Type. Thay đổi dữ liệu trong class bên trong struct A sẽ làm struct B (bản sao của A) bị thay đổi theo.
**Ví dụ:**

```swift
class Ref { var val = 0 }
struct Box { var ref = Ref() }
var box1 = Box()
var box2 = box1 // box1 và box2 chứa 2 con trỏ trỏ chung về 1 ô nhớ Ref
box2.ref.val = 10 // box1.ref.val cũng thành 10

```

### 34. Cơ chế hệ thống tự xây dựng để tối ưu hóa việc sao chép vùng nhớ Heap cho mảng và chuỗi là gì, và làm sao để tự cài đặt nó?

**Ý chính:** Copy-on-Write (CoW). Dùng `isKnownUniquelyReferenced` để tự cài đặt.
**Diễn giải:** Chỉ cấp phát ô nhớ mới khi có thao tác ghi dữ liệu và Reference Count của object nội bộ lớn hơn 1. Giúp tiết kiệm chi phí copy cho dữ liệu lớn.
**Ví dụ:**

```swift
struct DataBuffer {
    private var ref = NSMutableData()
    mutating func append(_ byte: UInt8) {
        if !isKnownUniquelyReferenced(&ref) {
            ref = ref.mutableCopy() as! NSMutableData // Copy khi có người share
        }
        // Ghi dữ liệu
    }
}

```

### 35. Bảng tra cứu nào được hệ thống tạo ra ngầm để quản lý việc gọi hàm của các đối tượng bị ẩn sau một Existential Type (`any`)?

**Ý chính:** Protocol Witness Table (PWT) cho method và Value Witness Table (VWT) cho bộ nhớ.
**Diễn giải:** Do không biết object thực tế lớn bao nhiêu và nằm ở đâu, hệ thống dùng VWT để quản lý vòng đời (allocate, copy, destroy) và dùng PWT để trỏ đến các thân hàm cụ thể ở thời điểm chạy. Điều này ngăn chặn Compiler thực hiện Inlining.
**Ví dụ:**

```swift
protocol Drawable { func draw() }
// Phải tra cứu PWT để biết `draw()` thực tế của Circle hay Square
func render(item: any Drawable) { item.draw() } 

```

### 36. Kỹ thuật biên dịch nào giúp triệt tiêu hoàn toàn chi phí tra cứu bảng hàm ảo khi làm việc với Generics?

**Ý chính:** Generics Specialization (Đặc biệt hóa).
**Diễn giải:** Khi bật Whole Module Optimization, Compiler phân tích các kiểu dữ liệu thực tế truyền vào hàm Generic và tự động sinh ra các phiên bản hàm tĩnh (ví dụ hàm dành riêng cho `Int`, riêng cho `String`). Biến Dynamic Dispatch thành Static Dispatch.
**Ví dụ:**

```swift
func add<T: Numeric>(_ a: T, _ b: T) {}
// Compiler sinh ra ngầm: 
// func add_Int(_ a: Int, _ b: Int) {}

```

### 37. Giải pháp nào dùng để thiết lập ràng buộc chặt chẽ lên các kiểu dữ liệu ẩn danh trong phần mở rộng của giao thức?

**Ý chính:** `where` clause trên `associatedtype`.
**Diễn giải:** Cho phép bổ sung thêm hàm vào Protocol nhưng chỉ kích hoạt nếu Type cụ thể thỏa mãn điều kiện nhất định, ví dụ bắt buộc phần tử của Collection phải hỗ trợ so sánh.
**Ví dụ:**

```swift
extension Collection where Element: Equatable {
    func removeDuplicates() -> [Element] { /* ... */ }
}

```

### 38. Cú pháp khai báo tắt trong Swift 5.7+ giúp rút gọn việc dùng `where clause` cho các cấu trúc kiểu chứa tham số phụ là gì?

**Ý chính:** Primary Associated Types (`some Protocol<Type>`).
**Diễn giải:** Cho phép khai báo nhanh Generic constraint ngay tại tên Protocol, giúp mã nguồn declarative hơn thay vì phải viết func generic dài dòng với dấu ngoặc vuông và where.
**Ví dụ:**

```swift
// Khai báo giao thức có primary type
protocol Storage<Item> { associatedtype Item }

// Sử dụng gọn gàng
func fetch() -> some Storage<Int> { ... }

```

### 39. Khi một hàm closure bắt một biến đếm kiểu Int bên ngoài thân hàm và thay đổi biến đó, biến đếm này thay đổi cơ chế lưu trữ như thế nào?

**Ý chính:** Biến được nâng cấp (promoted) từ Stack lên Heap (bọc trong Heap Box).
**Diễn giải:** Dù `Int` là Value Type, nhưng vì nó bị bắt vào closure (vốn sống trên Heap) và bị thay đổi (`mutated`), trình biên dịch phải đẩy biến đó lên Heap để duy trì trạng thái chung giữa môi trường ngoài và trong closure.
**Ví dụ:**

```swift
var counter = 0 // Bị đẩy lên Heap
let increment = { counter += 1 }

```

### 40. Từ khóa nào báo cho trình biên dịch biết hàm cấp cao chỉ sinh ra lỗi nếu khối mã người dùng truyền vào bên trong nó sinh ra lỗi?

**Ý chính:** `rethrows`.
**Diễn giải:** Thiết kế API thân thiện. Nếu truyền closure bình thường, gọi hàm không cần `try`. Nếu truyền closure có throws, bắt buộc gọi hàm với `try`.
**Ví dụ:**

```swift
func execute(block: () throws -> Void) rethrows {
    try block()
}

```

### 41. Tại sao việc định nghĩa một phương thức bên trong class bằng `extension` lại thay đổi cơ chế gọi hàm hệ thống so với định nghĩa trực tiếp trong class?

**Ý chính:** Phương thức trong extension của class mặc định gọi qua Static Dispatch/Direct Dispatch (không có trong vtable).
**Diễn giải:** Kế thừa từ Objective-C, class dùng Virtual Table. Nhưng extension không thể chèn thêm hàm vào vtable đã chốt lúc biên dịch class gốc (trừ trường hợp dùng `@objc dynamic`). Do đó, không thể `override` phương thức nằm trong extension.
**Ví dụ:**

```swift
class Base {}
extension Base { func doWork() {} } // Static Dispatch, không thể override ở class con

```

### 42. Cấu trúc bộ nhớ của con trỏ yếu (weak) và con trỏ không sở hữu (unowned) khác nhau ở tầng quản lý tham chiếu như thế nào?

**Ý chính:** `weak` dùng Side Table để an toàn gán `nil`; `unowned` trỏ thẳng Heap Object (chỉ tăng Unowned RC).
**Diễn giải:** Khi object bị hủy, `weak` qua Side Table sẽ dọn dẹp tham chiếu về `nil`. `unowned` không có Side Table, nếu object chết mà vẫn truy cập vào `unowned pointer`, ứng dụng sẽ crash do Dangling Pointer.
**Ví dụ:**

```swift
weak var safeRef: Object? // Tốn kém hơn do Side Table
unowned let fastRef: Object // Nhanh hơn nhưng rủi ro crash

```

### 43. Cơ chế giúp Swift 5.9+ có thể khai báo một hàm nhận không giới hạn số lượng các tham số kiểu dữ liệu khác biệt nhau là gì?

**Ý chính:** Parameter Packs (Variadic Generics với `each` và `repeat`).
**Diễn giải:** Khắc phục nhược điểm phải viết overload thủ công cho 1 tham số, 2 tham số, n tham số (như `ViewBuilder` cũ). Trình biên dịch sẽ tự động mở gói và ánh xạ từng tham số tương ứng.
**Ví dụ:**

```swift
func log<each T>(_ items: repeat each T) {
    // Xử lý n kiểu dữ liệu khác nhau
}

```

### 44. Yêu cầu `Self` (chữ S hoa) bên trong giao thức gây ra hậu quả gì đối với việc lưu trữ biến kiểu giao thức đó?

**Ý chính:** Khiến Protocol mất đi khả năng sử dụng như một Existential Type (Dynamic Dispatch) trong các phiên bản Swift cũ, bắt buộc chuyển thành Static Dispatch.
**Diễn giải:** `Self` yêu cầu trình biên dịch phải biết chính xác kiểu class/struct nào đang thực thi mã. Nếu gộp thành mảng `[Protocol]`, trình biên dịch không thể chắc chắn `Self` lúc chạy là gì, gây lỗi "Protocol can only be used as a generic constraint".
**Ví dụ:**

```swift
protocol Clonable { func clone() -> Self }
// let items: [Clonable] = [] // Lỗi do có chứa `Self`

```

### 45. Bộ đôi thuộc tính đặc biệt nào được sinh ra để Swift tương tác mượt mà với các ngôn ngữ không có kiểu tĩnh như Python hay Ruby?

**Ý chính:** `@dynamicMemberLookup` và `@dynamicCallable`.
**Diễn giải:** Cho phép gọi các thuộc tính và hàm không tồn tại ở thời điểm biên dịch. Trình biên dịch chuyển các cú pháp chấm (`.property`) thành hàm nhận tham số string (tên thuộc tính) để tự xử lý ở runtime.
**Ví dụ:**

```swift
@dynamicMemberLookup
struct JSON {
    subscript(dynamicMember member: String) -> String { return "" }
}

```

### 46. Từ khóa nào bắt buộc các lớp con phải cung cấp bản triển khai cho một hàm khởi tạo đã được quy định trong giao thức?

**Ý chính:** `required`.
**Diễn giải:** Khi protocol yêu cầu `init`, một class tuân thủ protocol phải đảm bảo bất kỳ class con nào kế thừa nó cũng có `init` này. Đánh dấu `required` để đảm bảo tính an toàn kiến trúc.
**Ví dụ:**

```swift
protocol Creatable { init() }
class Base: Creatable { required init() {} }

```

### 47. Kỹ thuật sử dụng một tham số kiểu generic nhưng không lưu trữ bất kỳ dữ liệu nào của kiểu đó bên trong cấu trúc gọi là gì?

**Ý chính:** Phantom Types (Kiểu bóng ma).
**Diễn giải:** Dùng Generics như một cái nhãn dán (tag) để trình biên dịch kiểm tra trạng thái ở compile-time, ngăn chặn lỗi logic business (ví dụ: không thể cộng lượng tiền VND với USD).
**Ví dụ:**

```swift
enum VND {}
enum USD {}
struct Money<Currency> { var amount: Double }
let vn = Money<VND>(amount: 10) // Không thể gán nhầm cho Money<USD>

```

### 48. Sự khác biệt giữa `Any` và `AnyObject` ở cấp độ kiến trúc hệ thống là gì?

**Ý chính:** `Any` đại diện cho mọi kiểu dữ liệu (cả Value và Reference type); `AnyObject` đại diện riêng cho Reference Type (Class).
**Diễn giải:** `AnyObject` thực chất là một protocol ngầm định mà mọi class đều tuân thủ. Dùng `AnyObject` khi muốn đảm bảo đối tượng truyền vào phải có tính chất lưu trữ trên Heap và chia sẻ con trỏ.
**Ví dụ:**

```swift
protocol Delegate: AnyObject {} // Chỉ class mới được conform để dùng weak

```

### 49. Khái niệm đại diện cho một đường dẫn trỏ đến một thuộc tính cụ thể của đối tượng mà có thể lưu trữ như một biến giá trị là gì?

**Ý chính:** KeyPaths (`\Type.property`).
**Diễn giải:** Tách biệt "thao tác trỏ tới thuộc tính" khỏi "đối tượng chứa thuộc tính". Rất mạnh mẽ trong functional programming, SwiftUI bindings, và cho phép tạo các API đọc dữ liệu động an toàn.
**Ví dụ:**

```swift
struct User { let name: String }
let keyPath = \User.name
let u = User(name: "iOS")
print(u[keyPath: keyPath]) // "iOS"

```

### 50. Tại sao biến `lazy` không được đảm bảo an toàn trong môi trường xử lý đa luồng (Thread-safety) và cách xử lý?

**Ý chính:** `lazy` thực chất là một computed property kết hợp mutating. Nếu 2 luồng truy cập cùng lúc khi biến chưa khởi tạo, nó có thể được khởi tạo 2 lần.
**Diễn giải:** Cấu trúc ngầm của `lazy` dùng biến Optional nội bộ. Truy cập đồng thời gây ra Race Condition. Cần tự bọc logic lock (OSAllocatedUnfairLock, DispatchSemaphore) hoặc dùng `actor` thay vì phụ thuộc vào `lazy` trong concurrent context.
**Ví dụ:**

```swift
// Đoạn mã không an toàn đa luồng
class Data {
    lazy var expensive = { return KhởiTạoNặng() }()
}

```
