```text
App
 ↓

 ↓
Thread
 ↓
RunLoop
 ↓
System Framework
 ↓

```

Và quan trọng hơn:

```text

Background
      ↓
System policy
      ↓
Task / Operation
      ↓
Resource limitation
```

# I. PROCESS / THREAD

## 1. Một ứng dụng iOS đang chạy được xem là một thread hay một process?

**Ý chính:** `App process` chứa nhiều `threads`.

**Ý diễn giải:**
Khi app chạy, hệ điều hành tạo một process cho app. Process có address space và resource riêng, bên trong có thể có nhiều thread thực thi công việc.

**Ví dụ:**

```text
App Process
│
├── Main Thread
│
├── Background Thread
├── Background Thread
└── Other system-managed threads
```

Không nên đồng nhất:

```text
App = Thread
```

mà đúng hơn:

```text
App → Process → Threads
```

---

## 2. Vì sao một ứng dụng cần nhiều thread thay vì thực hiện mọi công việc trên một thread?

**Ý chính:** `Concurrency + responsiveness + parallel work`.

**Ý diễn giải:**
Main thread cần phản hồi UI. Công việc CPU hoặc I/O có thể được thực hiện ở execution context khác để giảm việc block UI. Hệ thống runtime quyết định scheduler và thread usage.

**Ví dụ:**

```swift id="34j4h6"
Task {
    let data = await loadData()

    await MainActor.run {
        updateUI(data)
    }
}
```

---

## 3. Một task đang chạy nhưng không có thread riêng cố định. Điều này có ý nghĩa gì?

**Ý chính:** `Task ≠ Thread`.

**Ý diễn giải:**
Task là unit của asynchronous work. Runtime có thể suspend task và tiếp tục nó trên execution resource phù hợp. Không nên viết architecture dựa trên giả định một task luôn gắn với một thread.

**Ví dụ:**

```swift id="oym3o7"
Task {
    await step1()

    // Có suspension point

    await step2()
}
```

---

# II. RUN LOOP / MAIN RUN LOOP

## 4. Vì sao main thread thường có một vòng lặp thay vì chạy một function rồi kết thúc?

**Ý chính:** `RunLoop` xử lý event liên tục.

**Ý diễn giải:**
Main RunLoop nhận và xử lý input, timer, source và các event của UI. Khi app đang hoạt động, nó liên tục chờ và xử lý event thay vì return khỏi `main()`.

**Ví dụ:**

```text
Main Thread
    ↓
Main RunLoop
    ↓
Wait for event
    ↓
Process event
    ↓
Layout / Display
    ↓
Wait again
```

---

## 5. Nếu bạn chạy một vòng lặp synchronous dài trên main thread, chuyện gì xảy ra?

**Ý chính:** `Main RunLoop bị block`.

**Ý diễn giải:**
RunLoop không có cơ hội xử lý touch, layout, animation hoặc display trong thời gian synchronous work chiếm main thread. Kết quả là UI đứng hoặc dropped frames.

**Ví dụ:**

```swift id="v6swn5"
for _ in 0..<100_000_000 {
    expensiveWork()
}
```

Nếu chạy trên main thread:

```text
Touch
  ↓
Không được xử lý
  ↓
Animation
  ↓
Không được cập nhật
  ↓
UI freeze
```

---

## 6. GCD queue và thread có phải là cùng một khái niệm không?

**Ý chính:** `Queue ≠ Thread`.

**Ý diễn giải:**
GCD quản lý task/block thông qua dispatch queues. Hệ thống quyết định thread thực thi. Một queue có thể được xử lý bởi các thread khác nhau theo runtime.

**Ví dụ:**

```swift id="g3i38c"
DispatchQueue.global().async {
    doWork()
}
```

Bạn yêu cầu enqueue work vào queue, không trực tiếp tạo và quản lý thread.

---

# III. GCD / OPERATIONQUEUE

## 7. Khi nào GCD phù hợp hơn việc tự tạo Thread?

**Ý chính:** `Thread management abstraction`.

**Ý diễn giải:**
GCD giúp enqueue work mà không phải quản lý lifecycle thread thủ công. Với phần lớn application-level work, đây là abstraction phù hợp hơn tạo Thread trực tiếp.

**Ví dụ:**

```swift id="z7gk3p"
DispatchQueue.global(qos: .userInitiated).async {
    let result = process()
    
    DispatchQueue.main.async {
        updateUI(result)
    }
}
```

---

## 8. OperationQueue khác GCD ở điểm nào khiến nó vẫn hữu ích?

**Ý chính:** `Operation dependency + cancellation + state`.

**Ý diễn giải:**
Operation cung cấp abstraction cao hơn cho một work unit và hỗ trợ dependency, cancellation, trạng thái executing/finished/cancelled. Nó phù hợp một số workflow phức tạp hoặc legacy architecture.

**Ví dụ:**

```swift id="q71g7w"
let operationA = BlockOperation {
    print("A")
}

let operationB = BlockOperation {
    print("B")
}

operationB.addDependency(operationA)

queue.addOperations(
    [operationA, operationB],
    waitUntilFinished: false
)
```

---

## 9. Nếu một Operation bị cancel, code bên trong có tự động dừng ngay không?

**Ý chính:** Cancellation thường là `cooperative`.

**Ý diễn giải:**
Cancel chỉ thay đổi trạng thái. Implementation của Operation phải kiểm tra cancellation và dừng công việc phù hợp. Điều này tương tự tư duy cancellation trong Swift Concurrency.

**Ví dụ:**

```swift id="a3i6id"
final class MyOperation: Operation {

    override func main() {

        for item in items {

            if isCancelled {
                return
            }

            process(item)
        }
    }
}
```

# IV. APP LIFECYCLE / SCENE LIFECYCLE

## 10. Vì sao một ứng dụng có thể cần hiểu cả app lifecycle và scene lifecycle?

**Ý chính:** `Process lifecycle ≠ UI scene lifecycle`.

**Ý diễn giải:**
Process là lifetime của application process. Scene đại diện cho một UI session/window. Một process có thể có nhiều scene và từng scene có lifecycle riêng.

**Ví dụ:**

```text
Application Process
│
├── Scene A
│   ├── Active
│   └── Background
│
└── Scene B
    ├── Active
    └── Background
```

---

## 11. Nếu một app có hai scene, bạn có nên lưu trạng thái navigation UI vào singleton global không?

**Ý chính:** Không nên mặc định. `Scene-specific state`.

**Ý diễn giải:**
Mỗi scene có thể có navigation stack và UI state khác nhau. Global singleton cho UI state dễ làm scene này ghi đè scene kia.

**Ví dụ:**

```text
Scene A
→ Product #1

Scene B
→ Product #99
```

Không nên:

```swift id="6f5v7r"
AppState.shared.currentProduct = 1
```

nếu đó thực sự là state riêng của scene.

---

## 12. Khi user đưa app vào background, bạn có đảm bảo mọi code đang chạy sẽ tiếp tục không?

**Ý chính:** Không. `Background execution is system-controlled`.

**Ý diễn giải:**
Khi app background, hệ thống có thể suspend process. Một Task bình thường không phải background execution guarantee. Muốn tiếp tục một loại work cụ thể phải dùng API/capability phù hợp.

**Ví dụ:**

```text
App Active
    ↓
Background
    ↓
System may suspend app
    ↓
Task execution không còn được đảm bảo
```

# V. BACKGROUND EXECUTION

## 13. Bạn có một Task đang tải dữ liệu và user nhấn Home. Task có chắc chắn chạy tới khi hoàn thành không?

**Ý chính:** Không. `Task lifetime` và `process lifetime` khác nhau.

**Ý diễn giải:**
Task nằm trong process. Nếu process bị suspended hoặc terminated, Task không thể tiếp tục như khi app foreground. Cần chọn cơ chế background phù hợp với loại công việc.

**Ví dụ:**

```swift id="qul7hh"
Task {
    let data = try await download()
    save(data)
}
```

Đoạn này không phải background execution guarantee.

---

## 14. Nếu cần tải file lớn trong khi app không foreground, bạn dùng cơ chế nào?

**Ý chính:** `Background URLSession`.

**Ý diễn giải:**
Background URLSession cho phép hệ thống quản lý long-running network transfer và có thể đánh thức app khi transfer hoàn tất phù hợp với lifecycle system.

**Ví dụ:**

```swift id="j8j6te"
let configuration =
    URLSessionConfiguration.background(
        withIdentifier: "com.example.download"
    )

let session = URLSession(
    configuration: configuration,
    delegate: self,
    delegateQueue: nil
)
```

---

## 15. Nếu cần hệ thống đánh thức app để thực hiện một công việc maintenance không gắn với user interaction, bạn sẽ xem xét gì?

**Ý chính:** `BGTaskScheduler`.

**Ý diễn giải:**
BGTaskScheduler cho phép đăng ký background work và để hệ thống quyết định thời điểm thực thi. Đây không phải timer chính xác.

**Ví dụ:**

```swift id="v4s9rm"
let request =
    BGProcessingTaskRequest(
        identifier:
            "com.example.refresh"
    )

request.requiresNetworkConnectivity = true

try BGTaskScheduler.shared.submit(
    request
)
```

---

## 16. Vì sao không nên dùng background task như một cách để chạy vòng lặp vô hạn?

**Ý chính:** `System resource policy`.

**Ý diễn giải:**
iOS kiểm soát CPU, memory và battery rất chặt. Background execution không phải quyền chạy process liên tục. Nếu use case cần continuous work, phải dùng capability phù hợp và chấp nhận system constraints.

**Ví dụ:**

```text
❌ Background

while true {
    pollServer()
}
```

Đây không phải thiết kế background hợp lệ.

# VI. PUSH NOTIFICATION

## 17. Silent push có đảm bảo app luôn được chạy background để xử lý dữ liệu không?

**Ý chính:** Không. `System may throttle/drop/defer`.

**Ý diễn giải:**
Push là một signal cho hệ thống. Silent/background notification không phải guarantee rằng app sẽ được chạy ngay hoặc chạy bao lâu tùy ý.

**Ví dụ:**

```text
Server
  ↓
Push
  ↓
APNs
  ↓
System
  ↓
Có thể đánh thức app
  ↓
Background processing
```

Không nên thiết kế critical data consistency dựa hoàn toàn vào việc push luôn được delivery và execute ngay.

---

## 18. Push notification khác WebSocket ở điểm architecture nào?

**Ý chính:** `System-mediated notification` vs `persistent connection`.

**Ý diễn giải:**
WebSocket giữ connection khi app/OS cho phép. Push đi qua APNs và hệ thống quản lý delivery. Push phù hợp signaling; WebSocket phù hợp realtime stream khi connection được duy trì.

**Ví dụ:**

```text
WebSocket

Client ←────────→ Server
   persistent connection


Push

Server
   ↓
APNs
   ↓
iOS
   ↓
App
```

# VII. SANDBOX / FILESYSTEM

## 19. Vì sao app iOS không thể tự do đọc file của app khác?

**Ý chính:** `Sandbox`.

**Ý diễn giải:**
Mỗi app có container và security boundary riêng. App chỉ truy cập tài nguyên được hệ thống cho phép hoặc được cấp thông qua API/entitlement phù hợp.

**Ví dụ:**

```text
App A Container

Documents
Library
tmp
```

Không thể tự ý:

```text
App B/Documents
```

---

## 20. Bạn cần chia sẻ một file giữa app chính và extension của cùng ứng dụng. Cơ chế nào phù hợp?

**Ý chính:** `App Groups`.

**Ý diễn giải:**
App Groups cho phép các target được cấu hình cùng access group chia sẻ container dữ liệu. Nó yêu cầu entitlement/configuration phù hợp.

**Ví dụ:**

```text
Main App
    │
    ├──── App Group Container
    │
Extension
```

Code:

```swift id="f6jt4p"
let url =
    FileManager.default
        .containerURL(
            forSecurityApplicationGroupIdentifier:
                "group.com.example.shared"
        )
```

# VIII. APP EXTENSIONS

## 21. Vì sao không nên giả định App Extension có lifecycle và resource giống Main App?

**Ý chính:** `Extension has separate lifecycle/resource limits`.

**Ý diễn giải:**
Extension là thành phần được system host và có thời gian/resource constraints riêng. Không nên coi nó như một process phụ của app có toàn bộ quyền và lifetime.

**Ví dụ:**

```text
Host App
    ↓
iOS
    ↓
Extension
    ↓
Limited execution
```

## 22. Nếu extension cần dùng credential mà main app đang lưu, bạn cần quan tâm điều gì?

**Ý chính:** `Shared Keychain access group + entitlements`.

**Ý diễn giải:**
Keychain item có access group phù hợp để app và extension cùng truy cập. Cấu hình signing/entitlement phải nhất quán.

**Ví dụ:**

```text
Main App
    ↓
Keychain Access Group
    ↑
Extension
```

# IX. DEEP LINK / URL SCHEME / UNIVERSAL LINK

## 23. Một app nhận URL `myapp://product/123`. Bạn sẽ xử lý flow như thế nào?

**Ý chính:** `URL Scheme → parsing → routing → feature`.

**Ý diễn giải:**
URL nên được xử lý ở navigation boundary. Parse URL thành một route có type-safe representation rồi đưa tới feature tương ứng.

**Ví dụ:**

```swift id="8afmgm"
enum Route {
    case product(id: String)
}

func parse(url: URL) -> Route? {

    guard url.scheme == "myapp",
          url.host == "product"
    else {
        return nil
    }

    return .product(
        id: url.lastPathComponent
    )
}
```

Sau đó:

```text
URL
 ↓
Route
 ↓
Coordinator
 ↓
Product Feature
```

---

## 24. Vì sao custom URL Scheme không phải lựa chọn hoàn hảo cho deep linking?

**Ý chính:** `Scheme ownership không tuyệt đối`.

**Ý diễn giải:**
Custom scheme không gắn với domain ownership như Universal Links. App khác có thể đăng ký cùng scheme, nên nó không cung cấp cùng mức domain association.

**Ví dụ:**

```text
myapp://product/123
```

phụ thuộc custom scheme.

Trong khi:

```text
https://example.com/product/123
```

có thể dùng Universal Links.

---

## 25. Universal Links giải quyết vấn đề gì?

**Ý chính:** `HTTPS-based deep linking + domain association`.

**Ý diễn giải:**
Universal Links cho phép URL HTTPS mở trực tiếp vào app khi domain được associate với app qua cấu hình xác thực phù hợp. Nếu app không có, URL vẫn có thể mở web.

**Ví dụ:**

```text
https://example.com/product/123

        ↓
    Universal Link
        ↓
       App
```

# X. PERMISSIONS / ENTITLEMENTS

## 26. Permission và entitlement khác nhau ở điểm nào?

**Ý chính:** `Permission = user authorization`; `Entitlement = app capability/system authorization`.

**Ý diễn giải:**
Permission thường yêu cầu user cho phép truy cập resource như camera/location. Entitlement là capability được cấp/cấu hình cho app qua signing và provisioning/system policy.

**Ví dụ:**

```text
Camera

App
 ↓
Entitlement/configuration
 ↓
Request user permission
 ↓
Camera access
```

---

## 27. Nếu user đã cấp camera permission, app có chắc chắn sử dụng được camera không?

**Ý chính:** Không. `Permission ≠ capability guarantee`.

**Ý diễn giải:**
Ngoài permission còn có thể có device capability, session state, app lifecycle hoặc system restrictions. Permission chỉ nói user đã cấp quyền ở mức đó.

**Ví dụ:**

```swift id="yg0v0w"
AVCaptureDevice.requestAccess(
    for: .video
) { granted in

    if granted {
        // Vẫn cần configure camera session
    }
}
```

---

## 28. Entitlement có thể được app tự ý thêm trong code runtime không?

**Ý chính:** Không. `Code signing / provisioning`.

**Ý diễn giải:**
Entitlement là một phần của signed app configuration. App không thể runtime tự cấp cho mình quyền hệ thống mà không qua signing/provisioning/platform mechanism.

**Ví dụ:**

```text
Developer Configuration
        ↓
Provisioning / Signing
        ↓
Entitlements
        ↓
Installed App
```

# XI. KEYCHAIN

## 29. Vì sao Keychain thường phù hợp hơn UserDefaults để lưu credential?

**Ý chính:** `Secure credential storage`.

**Ý diễn giải:**
UserDefaults phục vụ preferences. Keychain được thiết kế cho protected secrets và có access control/security attributes phù hợp.

**Ví dụ:**

```swift id="97thst"
let query: [String: Any] = [

    kSecClass as String:
        kSecClassGenericPassword,

    kSecAttrAccount as String:
        "refresh_token",

    kSecValueData as String:
        Data(token.utf8)
]

SecItemAdd(
    query as CFDictionary,
    nil
)
```

---

## 30. Khi logout, chỉ xóa access token khỏi memory đã đủ chưa?

**Ý chính:** Không. `Credential lifecycle + persistent cleanup`.

**Ý diễn giải:**
Nếu refresh token vẫn nằm trong Keychain hoặc cache user-scoped còn tồn tại, session có thể chưa thực sự được clear. Logout phải xử lý credential, in-memory state, cached user data và pending operations phù hợp.

**Ví dụ:**

```swift id="3et9uy"
func logout() {

    memoryToken = nil

    keychain.delete(
        account: "access_token"
    )

    keychain.delete(
        account: "refresh_token"
    )

    userCache.clear()

    pendingTasks.forEach {
        $0.cancel()
    }
}
```

# XII. SENIOR SYSTEM SCENARIOS

## 31. Interviewer hỏi:

> “App đang background, bạn có đảm bảo Task tiếp tục chạy không?”

**Ý chính:** Không. `Task lifecycle` phụ thuộc `process lifecycle` và system background policy.

**Ý diễn giải:**

Câu trả lời Senior nên đi:

```text
App foreground
      ↓
Task đang chạy
      ↓
User background app
      ↓
System có thể suspend process
      ↓
Task không được đảm bảo chạy tiếp
```

Nếu work cần tiếp tục:

```text
Loại work?
    ↓
Network transfer
    → Background URLSession

Maintenance / refresh
    → BGTaskScheduler

Realtime capability-specific
    → Background mode tương ứng
```

Không nên nói:

```text
"Task async nên vẫn chạy."
```

---

## 32. App đang background nhưng vẫn muốn thực hiện một database cleanup rất nặng. Bạn có thể chỉ tạo Task.detached không?

**Ý chính:** Không. `Detached task ≠ background execution entitlement`.

**Ý diễn giải:**
Task.detached chỉ thay đổi concurrency context; nó không cấp quyền chạy background. Process vẫn có thể bị suspend/terminate.

**Ví dụ:**

```swift id="b3x8xm"
Task.detached {
    cleanupDatabase()
}
```

Không biến work thành system-guaranteed background work.

---

## 33. Nếu app bị terminate khi background, bạn có chắc callback lifecycle cuối cùng sẽ chạy để save dữ liệu không?

**Ý chính:** Không. `Termination callback is not guaranteed`.

**Ý diễn giải:**
Không nên chờ một callback cuối cùng để persist critical state. State quan trọng phải được lưu incrementally khi thay đổi hoặc trước các lifecycle transition phù hợp.

**Ví dụ:**

```text
❌

Change state
    ↓
Chờ applicationWillTerminate
    ↓
Save
```

Tốt hơn:

```text
Change state
    ↓
Persist immediately / transactionally
```

---

## 34. Một app có nhiều scene nhưng lại dùng global `NavigationCoordinator.shared`. Rủi ro gì?

**Ý chính:** `Scene isolation violation`.

**Ý diễn giải:**
Coordinator global có thể không đại diện đúng navigation stack của từng scene. Action từ Scene A có thể ảnh hưởng Scene B.

**Ví dụ:**

```text
Scene A
    ↓
Coordinator.shared
    ↓
Navigation Stack A ?

Scene B
    ↓
Coordinator.shared
    ↓
Navigation Stack B ?
```

Một coordinator có thể nên gắn với scene/session cụ thể.

---

## 35. Một extension dùng chung database với app chính. Bạn sẽ kiểm tra những gì trước?

**Ý chính:** `App Groups + persistence concurrency + lifecycle + shared state`.

**Ý diễn giải:**
Không chỉ kiểm tra shared file. Cần xem cả hai target có thể truy cập dữ liệu đồng thời, schema/migration có an toàn, file locking/atomicity và ownership lifecycle.

**Ví dụ:**

```text
Main App
    │
    ├──── Shared Container
    │          ↓
    │       Database
    │
Extension
```

Cần tránh assumption rằng chỉ có một process writer.

# XIII. 10 CÂU BẪY SENIOR

## 36. “Async Task luôn chạy background.”

**Ý chính:** Sai.

**Ý diễn giải:**
`async` nói về suspension, không phải background execution.

---

## 37. “Background app nghĩa process vẫn chạy nhưng UI không hiển thị.”

**Ý chính:** Không đảm bảo.

**Ý diễn giải:**
App có thể bị suspended hoặc terminated tùy system state và policy.

---

## 38. “Task.detached giúp app tiếp tục chạy khi background.”

**Ý chính:** Sai.

**Ý diễn giải:**
Detached chỉ tạo task không kế thừa context. Nó không cấp background execution.

---

## 39. “GCD global queue là một background thread duy nhất.”

**Ý chính:** Sai.

**Ý diễn giải:**
Global queue là dispatch queue; runtime quản lý thread pool và scheduling.

---

## 40. “Mỗi scene là một process.”

**Ý chính:** Sai.

**Ý diễn giải:**
Nhiều scene thường có thể thuộc cùng application process.

---

## 41. “Permission được cấp nghĩa app được phép dùng capability đó trong mọi hoàn cảnh.”

**Ý chính:** Sai.

**Ý diễn giải:**
Còn system state, hardware availability, lifecycle, entitlement và framework constraints.

---

## 42. “Universal Link chỉ là custom URL scheme nhưng dùng HTTPS.”

**Ý chính:** Sai.

**Ý diễn giải:**
Universal Links có domain association và system routing semantics riêng.

---

## 43. “Keychain chắc chắn bị xóa khi app uninstall.”

**Ý chính:** Không nên giả định như vậy.

**Ý diễn giải:**
Keychain có lifecycle/security behavior khác sandbox files. Nếu requirement cần xóa credential, app phải chủ động quản lý.

---

## 44. “App extension chỉ là một UIViewController nằm trong app.”

**Ý chính:** Sai.

**Ý diễn giải:**
Extension được host và quản lý bởi system/host app, có lifecycle và resource limits riêng.

---

## 45. “applicationWillTerminate là nơi tốt để lưu toàn bộ app state.”

**Ý chính:** Sai.

**Ý diễn giải:**
Không thể dựa vào termination callback để đảm bảo persistence. Critical state nên được lưu khi có thay đổi hoặc tại lifecycle transitions phù hợp.

# SENIOR ANSWER PATTERN

Khi interviewer hỏi:

> **“App background thì Task có tiếp tục không?”**

Một câu trả lời tốt:

> “Không thể đảm bảo. Task là concurrency abstraction nằm trong process, còn khi app chuyển background thì execution của process chịu sự quản lý của hệ thống. App có thể bị suspend hoặc terminate. Nếu workload cần background execution, tôi sẽ chọn API phù hợp với loại công việc như background URLSession hoặc BGTaskScheduler thay vì dựa vào một Task bình thường.”

Đó là cách trả lời thể hiện bạn hiểu cả:

```text
Swift Concurrency
        +
iOS Runtime
        +
App Lifecycle
        +
System Scheduling
        +
Resource Constraints
```

chứ không chỉ nhớ API.
