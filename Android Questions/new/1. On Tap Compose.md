# CẤP ĐỘ 1: JUNIOR (CƠ BẢN)

## Chủ đề: Core Concepts & Layouts

### 1. Bộ công cụ UI hiện đại của Android hoạt động theo cơ chế nào?

**Ý chính:** Jetpack Compose - UI khai báo (Declarative), mô tả "cái gì" thay vì "làm thế nào".

**Diễn giải:** Thay vì thao tác trực tiếp với View qua `findViewById()` hay XML, bạn chỉ cần mô tả UI dựa trên State hiện tại. Khi State thay đổi, UI tự động cập nhật.

**Ví dụ:**
```kotlin
@Composable
fun Greeting(name: String) {
    Text(text = "Hello $name")
}
```

---

### 2. So sánh cách tiếp cận xây dựng UI giữa XML và Compose?

**Ý chính:** XML là Imperative (mệnh lệnh), Compose là Declarative (khai báo).

**Diễn giải:** XML yêu cầu bạn chỉ định từng bước thay đổi View. Compose chỉ cần bạn mô tả UI theo dữ liệu, framework tự xử lý việc cập nhật.

**Ví dụ:**
```kotlin
// XML (Imperative)
val textView = findViewById<TextView>(R.id.myText)
textView.text = "New text"

// Compose (Declarative)
@Composable
fun MyText(state: String) {
    Text(text = state) // UI tự cập nhật khi state thay đổi
}
```

---

### 3. Annotation đặc biệt để đánh dấu hàm tạo UI trong Compose là gì?

**Ý chính:** `@Composable` - biến dữ liệu thành giao diện.

**Diễn giải:** Hàm có annotation `@Composable` chuyển đổi dữ liệu thành UI. Chỉ gọi được trong hàm `@Composable` khác, không trả về giá trị mà phát sinh UI trực tiếp.

**Ví dụ:**
```kotlin
@Composable
fun SimpleText() {
    Text("Chào bạn!")
}

@Composable
fun MyScreen() {
    Column {
        SimpleText()
        Text("Dòng thứ 2")
    }
}
```

---

### 4. Cơ chế cập nhật UI khi dữ liệu thay đổi trong Compose hoạt động như thế nào?

**Ý chính:** Recomposition - vẽ lại UI khi State thay đổi.

**Diễn giải:** Khi State đầu vào của hàm `@Composable` thay đổi, Compose gọi lại hàm với dữ liệu mới. Chỉ những phần cần thiết được vẽ lại, tối ưu hiệu năng.

**Ví dụ:**
```kotlin
@Composable
fun ClickCounter() {
    var count by remember { mutableStateOf(0) }
    
    Column {
        Text("Bạn đã click: $count lần") // Chỉ dòng này recompose
        Button(onClick = { count++ }) {
            Text("Click me")
        }
    }
}
```

---

### 5. Công cụ để tùy chỉnh giao diện và hành vi của Composable là gì?

**Ý chính:** Modifier - định hình, trang trí và thêm hành vi cho UI.

**Diễn giải:** Dùng để điều chỉnh kích thước, padding, background, bo góc hoặc xử lý sự kiện. Thứ tự áp dụng Modifier ảnh hưởng trực tiếp đến kết quả hiển thị.

**Ví dụ:**
```kotlin
Text(
    text = "Click me",
    modifier = Modifier
        .padding(16.dp)
        .clickable { /* Xử lý sự kiện */ }
)
```

---

### 6. Thứ tự áp dụng Modifier có ảnh hưởng đến kết quả không?

**Ý chính:** Có - Modifier áp dụng theo thứ tự từ trên xuống (chuỗi xích).

**Diễn giải:** Compose áp dụng Modifier tuần tự. Padding trước background tạo khoảng trống bên ngoài màu nền. Background trước padding tạo khoảng trống bên trong màu nền.

**Ví dụ:**
```kotlin
// Background trước, Padding sau
// Kết quả: Padding nằm ngoài (khoảng trống màu nền mặc định)
Text(
    text = "Hello",
    modifier = Modifier
        .background(Color.Red)
        .padding(16.dp)
)

// Padding trước, Background sau
// Kết quả: Padding nằm trong (khoảng trống màu đỏ)
Text(
    text = "Hello",
    modifier = Modifier
        .padding(16.dp)
        .background(Color.Red)
)
```

---

### 7. Ba Layout cơ bản nhất để sắp xếp UI trong Compose?

**Ý chính:** Column (dọc), Row (ngang), Box (chồng lớp).

**Diễn giải:** Tương đương LinearLayout (vertical/horizontal) và FrameLayout trong XML. Column xếp theo chiều dọc, Row theo chiều ngang, Box chồng các phần tử lên nhau.

**Ví dụ:**
```kotlin
Column {
    Text("Dòng 1")
    Text("Dòng 2")
}
```

---

### 8. Layout nào dùng để chồng các phần tử UI lên nhau?

**Ý chính:** Box - tương đương FrameLayout.

**Diễn giải:** Dùng để xếp chồng các thành phần UI, phần tử khai báo sau nằm trên phần tử khai báo trước.

**Ví dụ:**
```kotlin
Box {
    Image(painterResource(R.drawable.background), contentDescription = null)
    Text("Chữ đè lên ảnh")
}
```

---

### 9. Cách căn chỉnh vị trí các phần tử con trong Column và Row?

**Ý chính:** Arrangement (trục chính) và Alignment (trục phụ).

**Diễn giải:** Column có trục chính dọc, trục phụ ngang. Row ngược lại. Arrangement điều chỉnh khoảng cách trên trục chính, Alignment căn chỉnh vị trí trên trục phụ.

**Ví dụ:**
```kotlin
Row(
    horizontalArrangement = Arrangement.SpaceBetween,
    verticalAlignment = Alignment.CenterVertically
) {
    Text("Trái")
    Text("Phải")
}
```

---

### 10. Cách tạo khoảng trống giữa các UI component?

**Ý chính:** Spacer - tạo khoảng cách cố định.

**Diễn giải:** Thay vì dùng padding nhiều lần, chèn Spacer với kích thước xác định giữa các phần tử để tạo khoảng cách rõ ràng.

**Ví dụ:**
```kotlin
Column {
    Text("A")
    Spacer(modifier = Modifier.height(16.dp))
    Text("B")
}
```

## Chủ đề: State & Lists (Cơ bản)

### 11. Cách giữ giá trị qua các lần Recomposition?

**Ý chính:** `remember` - lưu trữ giá trị trong bộ nhớ Compose.

**Diễn giải:** Không có `remember`, biến sẽ khởi tạo lại mỗi lần recompose. `remember` lưu giá trị vào Composition tree để tồn tại qua các lần vẽ lại.

**Ví dụ:**
```kotlin
val count = remember { mutableStateOf(0) }
```

---

### 12. Phân biệt `remember` và `rememberSaveable`?

**Ý chính:** `rememberSaveable` giữ dữ liệu qua configuration changes (xoay màn hình).

**Diễn giải:** `remember` mất dữ liệu khi Activity bị hủy. `rememberSaveable` lưu vào Bundle, tồn tại qua xoay màn hình và process death.

**Ví dụ:**
```kotlin
@Composable
fun MyTextField() {
    var text by remember { mutableStateOf("") } // Mất khi xoay màn hình
    var textSaved by rememberSaveable { mutableStateOf("") } // Giữ khi xoay màn hình
    
    TextField(
        value = textSaved,
        onValueChange = { textSaved = it }
    )
}
```

---

### 13. Kiểu dữ liệu để Compose theo dõi thay đổi và kích hoạt Recomposition?

**Ý chính:** MutableState - hộp chứa dữ liệu có thể quan sát.

**Diễn giải:** Khi giá trị trong MutableState thay đổi, Compose tự động phát hiện và kích hoạt Recomposition cho các Composable sử dụng nó.

**Ví dụ:**
```kotlin
var name by remember { mutableStateOf("An") }
```

---

### 14. Thay thế RecyclerView trong Compose để hiển thị danh sách dài?

**Ý chính:** LazyColumn/LazyRow - danh sách lazy loading.

**Diễn giải:** Chỉ render các phần tử hiển thị trên màn hình, tối ưu bộ nhớ cho danh sách lớn. Tương tự RecyclerView nhưng đơn giản hơn.

**Ví dụ:**
```kotlin
LazyColumn {
    items(100) { index -> 
        Text("Item $index") 
    }
}
```

---

### 15. Cách xử lý sự kiện click cho item trong LazyColumn?

**Ý chính:** `Modifier.clickable` trên Composable của item.

**Diễn giải:** Thêm modifier clickable vào layout bọc ngoài của mỗi item để bắt sự kiện click.

**Ví dụ:**
```kotlin
LazyColumn {
    items(list) { item ->
        Row(
            modifier = Modifier
                .fillMaxWidth()
                .clickable { onClick(item) }
                .padding(16.dp)
        ) {
            Text(item.name)
        }
    }
}
```

---

### 16. Cách hiển thị ảnh từ URL trong Compose?

**Ý chính:** Thư viện Coil hoặc Glide - `AsyncImage`.

**Diễn giải:** Compose không hỗ trợ load ảnh mạng mặc định. Sử dụng thư viện như Coil với composable `AsyncImage`.

**Ví dụ:**
```kotlin
AsyncImage(
    model = "https://example.com/image.jpg",
    contentDescription = "Mô tả ảnh"
)
```

---

### 17. Cấu trúc khung chuẩn Material Design cho một màn hình?

**Ý chính:** Scaffold - khung màn hình Material Design.

**Diễn giải:** Cung cấp slots cho TopBar, BottomBar, FloatingActionButton, Snackbar. Tự động xử lý padding và layout.

**Ví dụ:**
```kotlin
Scaffold(
    topBar = { TopAppBar { Text("Home") } }
) { paddingValues ->
    Box(modifier = Modifier.padding(paddingValues)) {
        Text("Nội dung chính")
    }
}
```

# CẤP ĐỘ 2: MID-LEVEL (TRUNG CẤP)

## Chủ đề: State Hoisting & Architecture

### 18. Kỹ thuật quản lý State để tăng khả năng tái sử dụng Composable?

**Ý chính:** State Hoisting - đẩy State lên component cha.

**Diễn giải:** Chuyển Composable từ Stateful (tự quản lý state) sang Stateless (nhận state từ bên ngoài). Tăng khả năng tái sử dụng và dễ test.

**Ví dụ:**
```kotlin
// Stateless Composable
@Composable
fun Counter(count: Int, onIncrement: () -> Unit) {
    Button(onClick = onIncrement) {
        Text("Số lần click: $count")
    }
}

// Stateful Composable (quản lý state ở cha)
@Composable
fun CounterScreen() {
    var count by remember { mutableStateOf(0) }
    Counter(count = count, onIncrement = { count++ })
}
```

---

### 19. Phân biệt Stateful và Stateless Composable?

**Ý chính:** Stateful tự quản lý state, Stateless nhận state từ tham số.

**Diễn giải:** Stateless linh hoạt, dễ tái sử dụng và test hơn. Pattern phổ biến: Stateful wrapper bọc Stateless UI.

**Ví dụ:**
```kotlin
// Stateless
@Composable
fun TextField(value: String, onValueChange: (String) -> Unit) { }

// Stateful wrapper
@Composable
fun StatefulTextField() {
    var text by remember { mutableStateOf("") }
    TextField(value = text, onValueChange = { text = it })
}
```

---

### 20. Cách kết nối ViewModel với Composable?

**Ý chính:** `viewModel()` hoặc `hiltViewModel()`.

**Diễn giải:** Lấy instance ViewModel trong Composable ở tầng Screen, sau đó collect StateFlow/LiveData để quan sát dữ liệu.

**Ví dụ:**
```kotlin
@Composable 
fun HomeScreen(viewModel: HomeViewModel = hiltViewModel()) {
    val state by viewModel.uiState.collectAsStateWithLifecycle()
    
    Text("Dữ liệu: ${state.data}")
}
```

---

### 21. Tại sao nên dùng `collectAsStateWithLifecycle()` thay vì `collectAsState()`?

**Ý chính:** Lifecycle-aware - tự động dừng collect khi app background.

**Diễn giải:** `collectAsStateWithLifecycle()` nhận biết lifecycle, ngừng thu thập khi app không hiển thị, tiết kiệm tài nguyên và pin.

**Ví dụ:**
```kotlin
@Composable 
fun HomeScreen(viewModel: HomeViewModel = viewModel()) {
    val state by viewModel.uiState.collectAsStateWithLifecycle()
}

class HomeViewModel : ViewModel() {
    private val _uiState = MutableStateFlow(HomeUiState())
    val uiState: StateFlow<HomeUiState> = _uiState.asStateFlow()
    
    fun updateData() {
        _uiState.update { it.copy(data = "New data") }
    }
}
```

---

### 22. Nguyên tắc luồng dữ liệu một chiều trong Compose?

**Ý chính:** Unidirectional Data Flow (UDF) - State xuống, Event lên.

**Diễn giải:** ViewModel gửi State xuống UI. UI gửi Event lên ViewModel xử lý. Dữ liệu chỉ chạy một chiều, dễ debug và maintain.

**Ví dụ:**
```kotlin
@Composable
fun LikeButton(
    likeCount: Int,           // State từ ViewModel
    onLikeClicked: () -> Unit // Event lên ViewModel
) {
    Button(onClick = onLikeClicked) {
        Text("Thích ($likeCount)")
    }
}

@Composable
fun PostScreen(viewModel: PostViewModel = viewModel()) {
    val uiState by viewModel.uiState.collectAsState()
    
    LikeButton(
        likeCount = uiState.likeCount,
        onLikeClicked = { viewModel.onLikeClicked() }
    )
}
```

## Chủ đề: Side-Effects

### 23. Khái niệm Side-Effect trong Compose?

**Ý chính:** Hành động ngoài phạm vi vẽ UI.

**Diễn giải:** Các tác vụ không liên quan trực tiếp đến rendering UI: gọi API, hiển thị Toast, navigation, logging.

**Ví dụ:**
```kotlin
@Composable
fun MyScreen(showToast: Boolean) {
    val context = LocalContext.current
    
    LaunchedEffect(showToast) {
        if (showToast) {
            Toast.makeText(context, "Thành công!", Toast.LENGTH_SHORT).show()
        }
    }
}
```

---

### 24. Cách chạy Coroutine khi Composable hiển thị hoặc key thay đổi?

**Ý chính:** `LaunchedEffect` - chạy coroutine theo lifecycle và key.

**Diễn giải:** Tự động hủy coroutine cũ và chạy lại khi key thay đổi. Hủy khi Composable rời khỏi Composition.

**Ví dụ:**
```kotlin
LaunchedEffect(userId) {
    viewModel.loadUserData(userId) // Gọi lại khi userId thay đổi
}
```

---

### 25. Phân biệt `LaunchedEffect` và `SideEffect`?

**Ý chính:** `LaunchedEffect` bất đồng bộ (coroutine), `SideEffect` đồng bộ (sau recompose).

**Diễn giải:** `LaunchedEffect` cho tác vụ async. `SideEffect` đồng bộ state Compose với non-Compose code sau mỗi recompose thành công.

**Ví dụ:**
```kotlin
@Composable
fun AnalyticsScreen(screenName: String) {
    SideEffect {
        Analytics.logScreenView(screenName) // Đồng bộ sau recompose
    }
}

@Composable
fun DataLoadingScreen(userId: String, viewModel: ViewModel) {
    LaunchedEffect(userId) {
        viewModel.loadData(userId) // Bất đồng bộ
    }
}
```

---

### 26. Side-effect cần cleanup khi Composable bị hủy?

**Ý chính:** `DisposableEffect` - có khối `onDispose` cleanup.

**Diễn giải:** Dùng khi cần đăng ký listener, observer và phải hủy đăng ký khi Composable rời Composition.

**Ví dụ:**
```kotlin
DisposableEffect(lifecycleOwner) {
    val observer = LifecycleEventObserver { _, event ->
        // Xử lý lifecycle event
    }
    lifecycleOwner.lifecycle.addObserver(observer)
    
    onDispose { 
        lifecycleOwner.lifecycle.removeObserver(observer)
    }
}
```

---

### 27. Cách tạo CoroutineScope trong callback sự kiện?

**Ý chính:** `rememberCoroutineScope` - scope cho event handler.

**Diễn giải:** `LaunchedEffect` tự chạy khi vào màn hình. `rememberCoroutineScope` dùng trong callback (onClick, onSwipe) để launch coroutine theo yêu cầu.

**Ví dụ:**
```kotlin
@Composable
fun ScrollToTopButton() {
    val scope = rememberCoroutineScope()
    val listState = rememberLazyListState()
    
    Button(onClick = {
        scope.launch {
            listState.animateScrollToItem(0)
        }
    }) {
        Text("Lên đầu trang")
    }
    
    LazyColumn(state = listState) {
        items(100) { Text("Item $it") }
    }
}
```

---

### 28. Tối ưu recomposition khi state phụ thuộc thay đổi liên tục?

**Ý chính:** `derivedStateOf` - chỉ recompose khi kết quả thay đổi.

**Diễn giải:** Bỏ qua các thay đổi trung gian, chỉ kích hoạt recomposition khi giá trị tính toán cuối cùng thực sự khác.

**Ví dụ:**
```kotlin
@Composable
fun ScrollableList() {
    val listState = rememberLazyListState()
    
    val showButton by remember {
        derivedStateOf {
            listState.firstVisibleItemIndex > 5
        }
    }
    
    Box {
        LazyColumn(state = listState) {
            items(100) { Text("Item $it") }
        }
        
        if (showButton) {
            FloatingActionButton(onClick = { /*...*/ }) {
                Text("↑")
            }
        }
    }
}
```

## Chủ đề: Deep Dive Lists & Animation

### 29. Tại sao nên cung cấp key cho items trong LazyColumn?

**Ý chính:** Giúp Compose nhận diện item chính xác khi danh sách thay đổi.

**Diễn giải:** Tương tự DiffUtil, key giúp Compose biết item nào thêm/xóa/di chuyển, tránh vẽ lại toàn bộ danh sách, tăng hiệu năng và animation mượt.

**Ví dụ:**
```kotlin
items(items = userList, key = { user -> user.id }) { user ->
    UserItem(user)
}
```

### 30. Cách tạo hiệu ứng ẩn/hiện UI mượt mà?

**Ý chính:** `AnimatedVisibility` - animation tự động.

**Diễn giải:** Thay thế visibility VISIBLE/GONE bằng các hiệu ứng fade, slide, expand có sẵn.

**Ví dụ:**
```kotlin
AnimatedVisibility(visible = isVisible) {
    Text("Nội dung ẩn hiện")
}
```

---

### 31. Cách animate thuộc tính UI (màu, kích thước)?

**Ý chính:** `animate*AsState` (ví dụ: `animateColorAsState`).

**Diễn giải:** Truyền giá trị đích, Compose tự tạo animation chuyển đổi mượt mà từ giá trị hiện tại.

**Ví dụ:**
```kotlin
val backgroundColor by animateColorAsState(
    if (isSelected) Color.Red else Color.Gray
)

Box(modifier = Modifier.background(backgroundColor)) {
    Text("Click me")
}
```

# CẤP ĐỘ 3: SENIOR (NÂNG CAO)

## Chủ đề: Performance & Custom Layouts

### 32. Ba giai đoạn vẽ UI trong Compose?

**Ý chính:** Composition → Layout → Drawing.

**Diễn giải:**
1. **Composition**: Chạy `@Composable` để xây dựng UI tree
2. **Layout**: Measure và place các component
3. **Drawing**: Vẽ lên Canvas

**Ví dụ:**
```kotlin
@Composable
fun OptimizedScrolling() {
    val scrollState = rememberScrollState()
    
    Box(
        modifier = Modifier
            .offset { IntOffset(0, scrollState.value) } // Bỏ qua Composition
    ) {
        // Nội dung không recompose khi cuộn
    }
}
```

---

### 33. Tối ưu hiệu năng khi state thay đổi liên tục (scroll, drag)?

**Ý chính:** Dùng lambda trong Modifier thay vì giá trị trực tiếp.

**Diễn giải:** Lambda modifier (như `offset { }`) bỏ qua Composition phase, chỉ chạy Layout/Drawing, tăng hiệu năng đáng kể.

**Ví dụ:**
```kotlin
// TỐT - chỉ Layout/Draw phase
Modifier.offset { IntOffset(0, scrollState.value) }

// XẤU - gây Recomposition
Modifier.offset(y = scrollState.value.dp)
```

---

### 34. Annotation để đánh dấu dữ liệu ổn định cho Compose?

**Ý chính:** `@Stable` và `@Immutable` - giúp skip recomposition.

**Diễn giải:**
- `@Immutable`: Dữ liệu không đổi sau khi tạo
- `@Stable`: Dữ liệu có thể đổi nhưng Compose được thông báo

**Ví dụ:**
```kotlin
@Immutable
data class User(val id: Int, val name: String)

@Stable
class UserState(initialName: String) {
    var name by mutableStateOf(initialName)
}
```

### 35. Vấn đề khi truyền `List` interface vào Composable?

**Ý chính:** `List` là Unstable, gây mất tính năng Skippable.

**Diễn giải:** Kotlin `List` có thể là mutable (ArrayList), Compose không chắc chắn nên luôn recompose. Dùng `ImmutableList` để giải quyết.

**Ví dụ:**
```kotlin
// XẤU - Unstable
data class MyState(val items: List<String>)

// TỐT - Stable
import kotlinx.collections.immutable.ImmutableList
import kotlinx.collections.immutable.toImmutableList

data class MyState(val items: ImmutableList<String>)

val state = MyState(listOf("A", "B").toImmutableList())
```

### 36. Cách tạo Custom Layout hoàn toàn tùy chỉnh?

**Ý chính:** Dùng `Layout` composable với logic measure/place tự viết.

**Diễn giải:** Nhận measurables, đo từng child, tính kích thước tổng, sau đó place các child vào vị trí mong muốn.

**Ví dụ:**
```kotlin
@Composable
fun SimpleColumn(
    modifier: Modifier = Modifier,
    content: @Composable () -> Unit
) {
    Layout(
        modifier = modifier,
        content = content
    ) { measurables, constraints ->
        val placeables = measurables.map { it.measure(constraints) }
        
        val height = placeables.sumOf { it.height }
        val width = placeables.maxOfOrNull { it.width } ?: 0
        
        layout(width, height) {
            var yPosition = 0
            placeables.forEach { placeable ->
                placeable.placeRelative(x = 0, y = yPosition)
                yPosition += placeable.height
            }
        }
    }
}
```

### 38. Phân biệt `staticCompositionLocalOf` và `compositionLocalOf`?

**Ý chính:** `static` cho dữ liệu ít đổi, `compositionLocalOf` cho dữ liệu thường đổi.

**Diễn giải:** `staticCompositionLocalOf` recompose toàn bộ cây khi thay đổi. `compositionLocalOf` chỉ recompose nơi sử dụng `.current`.

**Ví dụ:**
```kotlin
val LocalTheme = compositionLocalOf { LightTheme } // Hay đổi
val LocalLanguage = staticCompositionLocalOf { "vi" } // Ít đổi

@Composable
fun App() {
    CompositionLocalProvider(
        LocalTheme provides currentTheme,
        LocalLanguage provides "en"
    ) {
        MyScreen()
    }
}
```

### 46. Recomposition Loop là gì và cách phòng tránh?

**Ý chính:** Vòng lặp vô tận do thay đổi state trong thân Composable.

**Diễn giải:** Thay đổi state trực tiếp trong Composable body gây recompose liên tục. Chỉ thay đổi state trong side-effect hoặc event handler.

**Ví dụ:**
```kotlin
// XẤU - vòng lặp vô tận
@Composable
fun BadCounter() {
    var count by remember { mutableStateOf(0) }
    count++ // Recompose → count++ → recompose → ...
    Text("Count: $count")
}

// TỐT
@Composable
fun GoodCounter() {
    var count by remember { mutableStateOf(0) }
    
    Column {
        Text("Count: $count")
        Button(onClick = { count++ }) {
            Text("Tăng")
        }
    }
}
```

### 48. Cách đảm bảo Composable skippable?

**Ý chính:** Tham số đầu vào phải Stable/Immutable.

**Diễn giải:** Khi tất cả tham số là stable, Compose tự động skip recomposition nếu giá trị không đổi.

**Ví dụ:**
```kotlin
// Unstable - luôn recompose
@Composable
fun UserList(users: List<User>) { }

// Stable - skippable
@Composable
fun UserList(users: ImmutableList<User>) { }

@Immutable
data class User(val id: Int, val name: String)
```

### 49. Khác biệt giữa `SubcomposeLayout` và `Layout`?

**Ý chính:** `SubcomposeLayout` hoãn composition cho đến khi biết kích thước parent.

**Diễn giải:** Giải quyết bài toán: UI con cần biết kích thước thực của UI con khác để quyết định hiển thị.

**Ví dụ:**
```kotlin
@Composable
fun AdaptiveLayout(
    header: @Composable () -> Unit,
    content: @Composable (headerHeight: Int) -> Unit
) {
    SubcomposeLayout { constraints ->
        val headerPlaceable = subcompose("header") { header() }
            .first()
            .measure(constraints)
        
        val contentPlaceable = subcompose("content") {
            content(headerPlaceable.height)
        }.first().measure(constraints)
        
        layout(constraints.maxWidth, headerPlaceable.height + contentPlaceable.height) {
            headerPlaceable.place(0, 0)
            contentPlaceable.place(0, headerPlaceable.height)
        }
    }
}
```
